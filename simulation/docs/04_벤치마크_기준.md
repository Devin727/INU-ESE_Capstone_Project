# 04. 벤치마크 기준

벤치(`bench`)는 모델 × 배관 조합을 헤드리스로 돌려 같은 방식으로 평가합니다. 목적은 **실물을 만들었을 때 실제로 쓸 수 있는지**를 숫자로 보는 것입니다.

## 1. 실행 방식

- 조합마다 `sim.launch.py`를 헤드리스로 띄우고, `/cmd_vel`로 일정 속도(기본 0.06 m/s)를 줍니다.
- 종료 조건:
  - **PASS:** 끝 마개(배관 끝 좌표)에서 20cm 이내에 도착
  - **STUCK:** 15초 동안 진행률이 늘지 않음
  - **TIMEOUT:** 제한 시간(중심선 길이 ÷ 속도 × 2.5 + 20초) 초과
  - **FLIPPED:** 배관 밖으로 나가거나 바닥 아래로 떨어짐
- 시작 시 자세 정보가 안 오거나 측정이 이상하면(엔코더·자세 기록 없음) 한 번 더 측정합니다. 두 번째 결과를 씁니다.
- 실행 전후로 이전 실행의 시뮬을 모두 끕니다 (표식 `PIPE_BENCH`). 이 장치가 없던 시기 결과는 오염 가능성이 있습니다 ([06 문서](06_알려진_문제.md)).

## 2. 평가 항목

| 항목 (csv 열) | 정의 | 의미 |
|---|---|---|
| `align_max` (정렬) | 마디(`bench_spines`)의 축이 자기 위치의 배관 방향과 이루는 각도의 최댓값 [°] | 코너에서 마디가 배관과 일자인지 |
| `roll_max` (롤) | 몸통이 배관 축 둘레로 비틀린 각도의 최댓값 [°] (배관을 따라 옮긴 위쪽 기준) | 몸통 뒤틀림, 바퀴가 한쪽으로 쏠림 |
| `sat_s` (한계접촉) | 관절이나 스프링 슬라이더가 가동 범위 끝 2% 안에 있던 시간 합 [s] | 바퀴가 휘거나 관절이 막힘 |
| `slip_pct` (미끄러짐) | (엔코더 거리 − 실제 이동 거리) ÷ 실제 이동 거리 × 100 [%] | 바퀴 헛돎. 양수면 엔코더가 더 많이 셈 |
| `stall_s` (정체) | 진행 속도가 목표의 30% 아래였던 시간 [s] | 중간에 걸림 |
| `est_err_mm` (추정 오차) | 추측항법 위치와 정답 위치의 차이 (종료 시점) [mm] | 위치추정 품질 (10/27 과제와 직결) |
| `real_ok` (실물 OK) | 아래 합격 기준을 모두 만족하면 O | 실물 제작 기준 |

## 3. 실물 합격 기준 (`real_ok`)

| 조건 | 기준 |
|---|---|
| 도착 | PASS |
| 정렬 | `align_max` ≤ 15° |
| 롤 | `roll_max` ≤ 10° |
| 한계 접촉 | `sat_s` ≤ 0.5 s |
| 미끄러짐 | \|`slip_pct`\| ≤ 10% |
| 걸림 | `stall_s` ≤ 1.0 s |

- 기준은 팀이 정한 제안값입니다. 사용자는 "코너에서도 각도별로 일자"를 원했고, 그 기준을 정량화한 것입니다.
- 현실적으로 DV 90°(R61) 같은 급한 엘보에서는 정렬 15°를 만족하는 구조가 아직 없습니다. 엘보 중심선 길이가 마디 길이와 비슷해서 물리적으로 어렵습니다.
- 그래서 `real_ok`가 X여도 "도착 여부"와 "롤·미끄러짐"을 따로 비교하는 것이 유용합니다.

## 4. 해석할 때 주의

- 시뮬 결과는 추정 파라미터(모터, 마찰, 질량, 서보 토크 등) 위에서 나온 값입니다. [08 추정값 목록](08_추정값_목록.md)의 값이 바뀌면 결과도 바뀝니다.
- `oracle` 모드(배관 모양을 아는 제어)와 `tracked`의 `oracle_steer`는 **상한값**입니다. 실물에서는 센서로 대체해야 하므로 성능이 떨어집니다.
- 롤은 "몸통이 굴러간 각도"입니다. 설계에서 롤을 막지 않고 IMU로 기록하기로 했다면, 롤 자체보다 미끄러짐과 정렬이 더 중요할 수 있습니다.
- 한 조합을 한 번만 돌리면 결과가 흔들립니다 (같은 조건 3회 반복에서 통과·실패가 섞인 사례 있음). 중요한 판단은 최소 3회 반복하세요.
- 속도가 다르면 결과도 달라집니다 (예: 아래로 90°는 6 cm/s에서 3/3, 5 cm/s에서 2/3 통과).

## 5. 결과 파일

- `bench/<이름>.csv`: 조합별 한 줄. 열은 위 평가 항목과 같습니다.
- `bench/<이름>_logs/`: 조합별 시뮬 로그 (문제 원인 확인용).
- `bench/<이름>.txt` 또는 `*_progress.txt`: 진행 중 출력 (한 줄씩 쌓임).
