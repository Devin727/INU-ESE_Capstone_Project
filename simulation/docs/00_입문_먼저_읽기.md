# 00. 입문: ROS 2와 시뮬 도구, 처음부터 쓰는 법

처음 보는 분을 위한 문서입니다. 이 문서만 읽고 시뮬을 띄우고 로봇을 움직일 수 있는 것이 목표입니다. 세부 구조는 [01 구조와 실행](01_구조와_실행.md), 모델은 [02 차체 모델](02_차체_모델.md)에 있습니다.

---

## 1. 큰 그림: 이 시뮬은 무엇인가

우리는 **실제 로봇을 만들기 전에 컴퓨터 안에서 먼저 움직여 보는 시뮬레이션**을 만들었습니다.

```
   [배관 모양]   [로봇 모양]   [로봇의 두뇌(제어 프로그램)]
        \            |                /
         \           |               /
          v          v              v
        +----------------------------------+
        |  Gazebo (물리 시뮬레이터)          |  바퀴가 굴러가고, 벽에 닿고, 중력이 작용
        +----------------------------------+
                        ^       |
            명령(토크)  |       |  센서 값 (엔코더, IMU, ToF)
                        |       v
        +----------------------------------+
        |  ROS 2 (로봇 프로그램들을 연결)     |  여러 프로그램이 메시지로 대화
        +----------------------------------+
```

- **Gazebo**: 물리 세계입니다. 중력, 마찰, 충돌을 계산해서 "로봇이 실제로 이렇게 움직이면 어떻게 될지"를 보여 줍니다.
- **ROS 2**: 로봇 프로그램들을 연결하는 틀입니다. 제어 프로그램, 센서 프로그램, 평가 프로그램이 서로 메시지를 주고받습니다.
- **우리 패키지 (`pipe_robot_sim`)**: 배관, 로봇 모델, 제어 프로그램, 평가 도구를 묶은 것입니다.

---

## 2. ROS 2가 무엇인가

**ROS 2(Robot Operating System 2)**는 로봇 소프트웨어를 만들기 위한 **틀(프레임워크)**입니다. 이름에 "Operating System"이 붙어 있지만 Windows나 Linux 같은 OS는 아닙니다. Linux 위에서 돌아가는 프로그램들을 서로 연결하는 도구 모음입니다.

### 핵심 개념 5개

| 용어 | 쉽게 말하면 | 예시 (이 프로젝트) |
|---|---|---|
| **노드 (node)** | 하나의 일을 하는 작은 프로그램 | `motor_driver`(모터 제어), `encoder_sim`(엔코더), `odometry`(위치 계산) |
| **토픽 (topic)** | 노드들이 메시지를 던지고 받는 "방송 채널" | `/cmd_vel`(속도 명령), `/wheel_encoders`(엔코더 값) |
| **메시지 (message)** | 토픽으로 주고받는 데이터 한 덩어리 | `geometry_msgs/Twist` (속도 명령의 형식) |
| **발행 (publish) / 구독 (subscribe)** | 방송하기 / 듣기 | `motor_driver`는 `/cmd_vel`을 구독하고, `joint_follow`는 `/servo/...`를 발행 |
| **런치 (launch)** | 여러 노드를 한 번에 켜는 설정 파일 | `sim.launch.py`: 배관, 로봇, 노드 10여 개를 한 번에 시작 |

**비유:** 노드는 직원, 토픽은 사내 게시판입니다. 직원(노드)들은 게시판(토픽)에 글(메시지)을 올리고, 필요한 글을 읽어서 일합니다. 누가 누구에게 직접 말하지 않아도 게시판으로 연결됩니다.

### 우리 시뮬에서 메시지가 흐르는 순서

```
사람이 입력 ──> /cmd_vel (전진 5cm/s)
                    │
                    ▼
              motor_driver ──> 바퀴 토크 ──> Gazebo가 바퀴를 굴림
                                                  │
                    ┌─────────────────────────────┘
                    ▼
     Gazebo가 관절 각도 발행 ──> encoder_sim ──> /wheel_encoders
                    │                              │
                    ▼                              ▼
                 /imu                          odometry ──> /odom (추정 위치)
                                                   │
                                  Gazebo 정답 위치 ──┘──> 오차 계산
```

## 3. Gazebo와 ROS 2를 잇는 다리 (ros_gz_bridge)

Gazebo와 ROS 2는 서로 다른 메시지 언어를 씁니다. 그래서 **브리지(bridge)**가 번역을 맡습니다.

- `ros_gz_bridge`가 `sim.launch.py` 안에서 자동으로 켜집니다.
- 어떤 토픽을 번역할지는 실행할 때 만든 설정 파일에 적혀 있습니다. 사람이 직접 고칠 일은 거의 없습니다.
- 예: Gazebo의 바퀴 토크 명령 → ROS 2의 `/motor/<관절>/torque`

---

## 4. 파일 종류 (무엇을 어디서 고치는가)

| 파일 | 역할 | 고치는 사람 |
|---|---|---|
| `models/<이름>/*.urdf.xacro` | 로봇의 생김새 (몸통, 바퀴, 관절, 센서) | 로봇 설계자 |
| `models/<이름>/robot.yaml` | 로봇의 숫자 값 (질량, 스프링 강성, 서보 토크 등) | 설계 값을 바꿀 때 |
| `models/<이름>/layout.yaml` | 부품 배치 (위치, 크기, 무게) | 부품을 바꿀 때 |
| `config/courses.yaml` | 배관 모양과 엘보 규격 | 배관을 바꿀 때 |
| `launch/sim.launch.py` | 실행 순서와 노드 목록 | 실행 방식을 바꿀 때 |
| `pipe_robot_sim/*.py` | 노드와 도구의 프로그램 코드 | 제어 로직을 바꿀 때 |

**가장 자주 고치는 것은 `robot.yaml`입니다.** 숫자만 바꾸면 되고, 다시 빌드할 필요도 없습니다.

> **xacro란?** 로봇 모양을 적는 XML 파일에 계산식과 반복문을 넣을 수 있는 확장 형식입니다. 예를 들어 바퀴 3개를 120°씩 돌려 배치하는 식을 한 번만 쓰면 됩니다.

## 5. 처음 쓰는 순서 (10분)

이 PC에는 ROS 2 Humble, Gazebo, 우리 패키지가 이미 설치되어 있습니다.

### 5-1. 터미널 두 개를 엽니다

ROS 2 명령은 **터미널마다** 준비 명령을 한 번씩 실행해야 합니다. 새 터미널을 열 때마다 아래 두 줄을 실행하세요.

```bash
source /opt/ros/humble/setup.bash
source ~/Capstone_sim/install/setup.bash
```

> `source`는 "이 터미널에서 ROS 2 도구를 쓸 수 있게 준비하라"는 뜻입니다. 빠뜨리면 `command not found`나 `Package not found`가 뜹니다.

### 5-2. 첫 번째 터미널: 시뮬 시작

```bash
ros2 launch pipe_robot_sim sim.launch.py course:=straight model:=two_real gui:=true rviz:=false
```

- Gazebo 창이 뜨고, 로봇이 직관 배관 위에 놓입니다.
- 이 터미널은 **켜 두는 용도**입니다. 끌 때는 Ctrl+C.

### 5-3. 두 번째 터미널: 로봇에게 명령 보내기

```bash
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.05}}"
```

- 로봇이 5cm/s로 앞으로 움직입니다. 그만두려면 Ctrl+C.
- `-r 10`: 1초에 10번 보냅니다 (명령이 계속 살아 있게).

### 5-4. 세 번째 터미널 (선택): 로봇의 현재 위치 보기

```bash
ros2 topic echo --once /ground_truth/odom --field pose.pose.position
```

- `x`가 늘어나면 앞으로 가고 있는 것입니다.
- `--once`: 한 번만 보여 주고 끝냅니다.

### 5-5. 끝내기

1. 두 번째 터미널에서 Ctrl+C (명령 중단).
2. 첫 번째 터미널에서 Ctrl+C (시뮬 종료).
3. 가끔 Gazebo가 완전히 안 꺼질 때가 있습니다. 아래로 확인하세요.

```bash
ps -eo pid,args | grep "ign gazebo" | grep -v grep
```

- 아무것도 안 나오면 정상입니다.
- 무언가 나오면 맨 앞의 숫자(PID)를 골라 `kill -9 <PID>`로 끄세요.

## 6. 도구 한눈에 보기

| 도구 | 무엇을 하나 | 언제 쓰나 |
|---|---|---|
| `sim.launch.py` | 배관 + 로봇 + 노드를 한 번에 시작 | 시뮬을 보고 싶을 때 |
| `bench` | 여러 로봇 × 여러 배관을 자동으로 돌리고 점수 매기기 | 설계를 비교할 때 |
| `layout_check` | 부품이 로봇 몸통에 들어가는지 검사, 질량과 무게중심 계산, 배치도 그림 | 부품을 바꾸거나 배치를 정할 때 |
| `generate_world` | 배관 모양 파일(SDF)만 만들기 | 배관 디자인을 확인할 때 (보통은 launch가 자동으로 함) |
| `ros2 topic echo` | 토픽의 메시지 보기 | 센서 값, 로봇 상태 확인 |
| `ros2 topic pub` | 토픽에 메시지 보내기 | 로봇에게 명령 보낼 때 |
| `ros2 topic list` | 지금 돌고 있는 토픽 목록 | 어떤 데이터가 있는지 모를 때 |
| `ros2 node list` | 지금 돌고 있는 노드 목록 | 어떤 프로그램이 돌고 있는지 확인 |
| `colcon build` | 코드를 설치 가능한 형태로 만들기 | Python 코드나 노드를 새로 추가했을 때 |

## 7. 도구별 사용법

### 7-1. sim.launch.py (시뮬 실행)

```bash
ros2 launch pipe_robot_sim sim.launch.py [인자:값 ...]
```

| 인자 | 기본값 | 쓸 수 있는 값 | 뜻 |
|---|---|---|---|
| `course` | `straight` | `straight`, `elbow45`, `elbow90`, `demo`, `elbow45_up`, `elbow45_down`, `elbow90_up`, `elbow90_down`, `demo3d` | 배관 모양 |
| `model` | `three_wheel` | `two_real`, `two_active`, `three_segment`, `pirate_v`, `tracked` 등 | 로봇 모델 |
| `fitting90` | (코스 기본) | `dv90`, `dv_ll90`, `ts90` | 90° 엘보 종류 바꾸기 |
| `fitting45` | (코스 기본) | `dv45`, `ts45` | 45° 엘보 종류 바꾸기 |
| `gui` | `true` | `true`, `false` | Gazebo 창 띄우기 (`false`면 창 없이) |
| `rviz` | `true` | `true`, `false` | RViz 창 띄우기 (로봇 모양을 보는 창) |
| `fullscreen` | `false` | `true`, `false` | Gazebo 창을 화면 크기로 |

**예시**
```bash
# 45° 엘보를 대곡으로 바꿔서 two_real 보기
ros2 launch pipe_robot_sim sim.launch.py course:=elbow90 model:=two_real fitting90:=dv_ll90

# 창 없이 돌리기 (서버용, 빠름)
ros2 launch pipe_robot_sim sim.launch.py course:=demo model:=two_real gui:=false rviz:=false
```

> **주의:** `gui:=false`로 돌리면 화면이 없어서 로봇을 눈으로 못 봅니다. 대신 빠르게 돌아갑니다.

### 7-2. bench (여러 설계 자동 비교)

```bash
ros2 run pipe_robot_sim bench --models 모델1 모델2 --courses 배관1 배관2 --fittings "" dv_ll90 -o 결과.csv
```

| 옵션 | 뜻 | 예시 |
|---|---|---|
| `--models` | 비교할 로봇들 (띄어쓰기로 여러 개) | `two_real two_active` |
| `--courses` | 시험할 배관들 | `straight elbow90 demo3d` |
| `--fittings` | 엘보 종류 (`""`은 코스 기본) | `"" dv_ll90 ts90` |
| `--speed` | 전진 속도 [m/s] (기본 0.06) | `0.05` |
| `-o` | 결과 파일 이름 (csv) | `bench/결과.csv` |

- 실행하면 조합마다 한 줄씩 결과가 출력되고, 파일에도 쌓입니다.
- 조합 하나에 약 40~60초 걸립니다. 여러 개를 돌리면 시간이 오래 걸리니 백그라운드로 돌리는 것이 좋습니다.
- 결과 읽는 법은 [04 벤치마크 기준](04_벤치마크_기준.md)을 보세요.

**결과 한 줄 읽는 법**

```
two_real  elbow90  - PASS  실물OK O  정렬 12°  롤 8°  한계접촉 0s  미끄럼 3%  ...
```

| 표시 | 뜻 |
|---|---|
| `PASS` | 배관 끝까지 도착 |
| `STUCK` | 중간에 멈춤 |
| `FLIPPED` | 뒤집히거나 배관 밖으로 나감 |
| `실물OK O/X` | 실물 기준(정렬 15° 이내, 롤 10° 이내 등)을 모두 만족하면 O |
| `정렬` | 마디가 배관 방향과 틀어진 최대 각도 (작을수록 일자) |
| `롤` | 몸통이 배관 축을 따라 비틀린 최대 각도 (작을수록 안정) |
| `미끄럼` | 바퀴가 헛도는 정도 (작을수록 좋음) |

### 7-3. layout_check (부품 들어가는지 검사)

```bash
ros2 run pipe_robot_sim layout_check 모델이름                     # 검사만
ros2 run pipe_robot_sim layout_check 모델이름 --plot 배치도.png   # 배치도 그림도 저장
ros2 run pipe_robot_sim layout_check 모델이름 --apply             # 질량·무게중심을 robot.yaml에 반영
```

- 검사 결과에서 `✗`는 문제가 있는 부품입니다. 그 부품의 위치를 `layout.yaml`에서 고치고 다시 검사하세요.
- `배치 OK`가 나와야 합니다.
- 배치도 그림(`--plot`)에서 빨간 부품이 문제입니다. 회색 띠는 바퀴가 움직이는 공간이라 부품을 두면 안 됩니다.

### 7-4. ros2 topic (메시지 보기와 보내기)

```bash
ros2 topic list                                  # 지금 돌고 있는 토픽 목록
ros2 topic echo /wheel_encoders                  # 엔코더 값을 계속 보기 (Ctrl+C로 중단)
ros2 topic echo --once /odom                     # 한 번만 보기
ros2 topic info /cmd_vel                         # 이 토픽을 누가 보내고 받는지
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.05}}"   # 명령 보내기
```

**자주 보는 토픽**

| 토픽 | 내용 | 보는 이유 |
|---|---|---|
| `/cmd_vel` | 전진 속도 명령 | 로봇에 명령을 보낼 때 |
| `/wheel_encoders` | 바퀴 회전 횟수 | 바퀴가 돌고 있나 |
| `/imu` | 몸통 기울기와 회전 속도 | 몸통이 얼마나 기울었나 |
| `/odom` | 추측항법으로 계산한 위치 | 로봇이 자기 위치를 어떻게 아는지 |
| `/ground_truth/odom` | 시뮬 정답 위치 | 실제 위치 (평가용) |
| `/joint_states` | 모든 관절 각도 | 서보와 스프링 상태 |
| `/tof/front/points` | 앞쪽 거리 센서 (8×8) | 엘보 방향을 어떻게 보는지 |

### 7-5. ros2 node (프로그램 확인)

```bash
ros2 node list                  # 지금 돌고 있는 노드 목록
ros2 node info /motor_driver    # 이 노드가 무엇을 받고 무엇을 보내는지
```

### 7-6. colcon build (다시 빌드)

```bash
cd ~/Capstone_sim
colcon build --symlink-install
source install/setup.bash
```

- **다시 빌드가 필요한 경우:** 새 Python 노드나 새 실행 파일을 추가했을 때, 또는 `setup.py`를 고쳤을 때.
- **필요 없는 경우:** `robot.yaml`, `layout.yaml`, `.urdf.xacro`, `courses.yaml` 같은 설정 파일을 고쳤을 때. 바로 반영됩니다 (`--symlink-install` 덕분).

## 8. 용어 사전

| 용어 | 뜻 |
|---|---|
| **ROS 2** | 로봇 프로그램을 연결하는 틀. 노드·토픽·메시지로 구성 |
| **노드 (node)** | 하나의 역할을 하는 프로그램 |
| **토픽 (topic)** | 노드들이 메시지를 주고받는 채널 이름 (예: `/cmd_vel`) |
| **메시지 (message)** | 토픽으로 오가는 데이터 한 덩어리 |
| **런치 (launch)** | 여러 노드를 한 번에 켜는 설정 |
| **패키지 (package)** | 관련 파일과 노드를 묶은 폴더 (여기서는 `pipe_robot_sim`) |
| **colcon** | ROS 2 패키지를 빌드하는 도구 |
| **Gazebo** | 물리 시뮬레이터 (중력, 마찰, 충돌 계산) |
| **SDF / URDF** | 세계(배관)와 로봇 모양을 적는 파일 형식 |
| **xacro** | URDF에 계산식을 넣을 수 있는 확장 형식 |
| **관절 (joint)** | 두 부품을 잇는 회전 또는 이동 부분 |
| **링크 (link)** | 관절 사이의 단단한 부품 (몸통, 바퀴 등) |
| **서보 (servo)** | 지정한 각도로 움직이는 모터 (MG90S 등) |
| **토크 (torque)** | 돌리는 힘 [N·m] |
| **엔코더 (encoder)** | 바퀴가 몇 번 돌았는지 세는 센서 |
| **IMU** | 자이로(회전 속도)와 가속도를 재는 센서 (자세 파악용) |
| **ToF** | 빛이 되돌아오는 시간으로 거리를 재는 센서 |
| **롤 / 피치 / 요** | 몸통의 세 가지 기울기. 롤은 축을 따라 비틀림, 피치는 위아래, 요는 좌우 |
| **정답 (ground truth)** | 시뮬이 아는 진짜 위치. 추정이 맞는지 비교할 때 사용 |
| **추측항법 (odometry)** | 바퀴 회전과 자세로 위치를 계산하는 방법 |
| **헤드리스 (headless)** | 화면 없이 돌리는 방식 |
| **PID** | 목표 속도와 현재 속도의 차이로 모터 출력을 조절하는 방식 |
| **도메인 ID (ROS_DOMAIN_ID)** | 같은 네트워크에서 프로그램끼리 서로 보이는 범위. 벤치는 77 사용 |
| **IGN_PARTITION** | Gazebo끼리 서로 보이는 범위 |
| **PASS / STUCK / FLIPPED** | 벤치의 결과 표시 (도착 / 멈춤 / 뒤집힘) |

## 9. 자주 생기는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| `command not found: ros2` | ROS 2 준비 명령을 안 함 | `source /opt/ros/humble/setup.bash` 실행 |
| `Package 'pipe_robot_sim' not found` | 우리 패키지 준비를 안 함 | `source ~/Capstone_sim/install/setup.bash` 실행 |
| `No executable found` | 새 노드를 추가했는데 빌드 안 함 | `colcon build --symlink-install` 후 다시 source |
| Gazebo 창이 안 뜸 | 화면이 없는 환경 (원격 접속 등) | `gui:=false`로 돌리거나 화면 있는 PC에서 실행 |
| 실행할 때마다 로봇 위치가 이상함 | 이전 실행의 Gazebo가 남아 있음 | 5-5절의 `ps` 명령으로 확인 후 끄기 |
| `XML parsing error` | 로봇 모양 파일(xacro)의 문법 실수 | 가장 최근에 고친 부분 확인. 주석(`<!-- -->`) 안에 `--`를 쓰면 안 됨 |
| 로봇이 움직이지 않음 | 전진 명령(`/cmd_vel`)을 안 보냄 | 5-3절의 `topic pub` 명령 실행 |
| 벤치 결과가 같은 조건에서 들쭉날쭉 | 시뮬이 남아서 서로 섞임 | 벤치는 자동 정리함. 수동 실행이 끼어 있지 않은지 확인 |
