# 01. 구조와 실행

## 1. 폴더 구성

```
simulation/
  README.md                       실행 요약
  docs/                           이 문서
  bench/                          벤치 결과 (csv), 로그 (*_logs/) — 처음 실행 때 생김
  src/pipe_robot_sim/
    config/courses.yaml           배관 규격, 엘보 프리셋, 코스 정의
    config/sim.rviz               RViz 설정
    launch/sim.launch.py          실행 진입점 (배관·로봇·노드를 한 번에 띄움)
    models/<이름>/                차체 모델 (현재 없음, 규약은 02 문서)
    pipe_robot_sim/*.py           노드와 도구
```

## 2. 빌드

```bash
cd ~/INU-ESE_Capstone_Project/simulation
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash
```

- `--symlink-install`이라 **이미 있는 yaml·xacro 수정은 재빌드 없이 바로 반영**됩니다.
- 새 파일(모델 폴더, 노드)을 추가했거나 `setup.py`를 고쳤을 때만 다시 빌드합니다.
- 다른 Python 가상환경이 켜져 있으면 ROS가 깨질 수 있습니다. ROS 노드는 `/usr/bin/python3` (3.10)로 돕니다.

## 3. 실행

```bash
# 배관만 보기 (모델 없이)
ros2 launch pipe_robot_sim sim.launch.py course:=demo

# 모델이 생긴 뒤
ros2 launch pipe_robot_sim sim.launch.py course:=demo3d model:=<모델>
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.05}}"   # 다른 터미널, 5 cm/s 전진
```

| 인자 | 값 | 설명 |
|---|---|---|
| `course` | `straight`(기본), `elbow45`, `elbow90`(왼쪽), `elbow90_right`, `demo`, `elbow45_up`, `elbow45_down`, `elbow90_up`, `elbow90_down`, `demo3d` | 배관 코스 (`courses.yaml`) |
| `model` | `models/` 아래 폴더 이름. 비우면(기본) 배관만 | 차체 모델 |
| `fitting90` | `dv90`, `dv_ll90`, `ts90` | 코스 안의 90° 엘보 교체 |
| `fitting45` | `dv45`, `ts45` | 코스 안의 45° 엘보 교체 |
| `suspension` | `all`, `top` | xacro로 넘기는 바퀴 스프링 구성 (모델이 쓰는 경우만) |
| `imu_mode` | `gyro`, `orientation` | odometry의 자세 계산 방식 |
| `gui` | `true`, `false` | Gazebo 창 |
| `rviz` | `true`, `false` | RViz 창 |
| `fullscreen` | `true`, `false` | Gazebo 창을 화면 크기로 (창 크기만 바꿈) |

- 창 없이 돌리려면 `gui:=false rviz:=false`.
- 없는 모델 이름을 주면 "모델 없음"과 있는 모델 목록을 출력하고 멈춥니다.

## 4. 노드

| 노드 | 역할 | 언제 뜨나 |
|---|---|---|
| `pipe_markers` | RViz용 배관 표시 | 항상 |
| `odometry` | 엔코더 + IMU 추측항법. 정답(`/ground_truth/odom`)과 위치 오차를 로그로 출력 | 모델 있을 때 |
| `encoder_sim` | 바퀴 관절 각도를 엔코더 카운트로 바꿈 (CPR 기준) | `wheel_joints`가 있을 때 |
| `motor_driver` | `/cmd_vel`을 바퀴 토크로 바꿈. 모드: `speed_pid`(바퀴별 속도 PID), `open_loop`(피드백 없음), `diff`(평균 속도만 PID, 모든 바퀴 같은 토크) | `wheel_joints`가 있을 때 |
| `imu_assist` | IMU 보조 제어: 가속도+자이로 상보 필터로 롤을 추정해 굴림 바퀴 토크로 목표 롤 유지, 자이로 z를 `/steer_cmd`로 보내 엘보에서 좌우 바퀴 속도차 | `robot.yaml`에 `imu_assist: true` |
| `bench` | 모델 × 배관 일괄 주행과 평가 (헤드리스) | 도구 |
| `layout_check` | 부품 배치 검사, 질량·무게중심 계산, 배치도 그림 | 도구 |
| `generate_world` | 배관 SDF 파일만 생성 | 도구 |

- 관절 서보 제어 노드는 없습니다. 능동 관절은 `/servo/<관절>`에 각도를 직접 보내거나, 새 제어 노드를 만들어야 합니다.
- `imu_assist` 파라미터 (`robot.yaml`): `roll_target_deg`, `roll_kp`, `roll_kd`, `roll_max_torque`, `roll_sign`(토크 방향), `roll_filter_alpha`, `steer_gain`(0 = 좌우 속도차 끔). 좌우 속도차를 쓰려면 `wheel_sides`, `track_separation`도 필요합니다.

## 5. 주요 토픽

| 토픽 | 타입 | 내용 |
|---|---|---|
| `/cmd_vel` | Twist | 목표 전진 속도 (`linear.x`), 좌우 속도차 조향 (`angular.z`, `wheel_sides` 설정 시) |
| `/wheel_encoders` | Int64MultiArray | 바퀴별 누적 엔코더 카운트 |
| `/imu` | Imu | 모델의 IMU 센서 |
| `/joint_states` | JointState | 모든 관절 각도와 속도 |
| `/servo/<관절>` | Float64 | 능동 관절 각도 명령 [rad] |
| `/motor/<관절>/torque` | Float64 | 바퀴 토크 명령 [N·m] |
| `/tof/front`, `/tof/left`, `/tof/right` | LaserScan | ToF 거리 |
| `/tof/front/points` | PointCloud2 | 전방 멀티존 ToF |
| `/ground_truth/odom` | Odometry | Gazebo 정답 자세 (평가용) |
| `/odom` | Odometry | 추정 자세 (엔코더 + IMU) |
| `/gz_poses` | TFMessage | 링크별 정답 자세 (bench의 마디 정렬 평가용) |
| `/pipe_markers` | MarkerArray | RViz 배관 |
| `/steer_cmd` | Float64 | 좌우 속도차 조향 [rad/s] (`imu_assist` → `motor_driver`) |
| `/imu_assist/roll` | Float64 | `imu_assist`가 추정한 롤 [deg] |

## 6. 벤치마크 실행

```bash
cd ~/INU-ESE_Capstone_Project/simulation
source install/setup.bash
export ROS_DOMAIN_ID=77 IGN_PARTITION=bench
ros2 run pipe_robot_sim bench --models <모델> \
    --courses straight elbow90 demo3d --fittings "" dv_ll90 ts90 \
    -o bench/결과이름.csv
```

- `--models`는 필수입니다.
- `--fittings`의 엘보는 코스에 같은 각도 엘보가 있을 때만 적용됩니다 (예: `dv_ll90`은 90° 엘보가 있는 코스에만).
- 결과는 `bench/결과이름.csv`, 실행 로그는 `bench/결과이름_logs/`에 저장됩니다. 조합 1개당 헤드리스로 약 40~60초.
- 벤치 실행 중에는 다른 시뮬을 띄우지 마세요. 같은 토픽을 써서 결과가 섞입니다.
- 평가 항목과 합격 기준은 [04 벤치마크 기준](04_벤치마크_기준.md).

## 7. 부품 배치 검사

```bash
ros2 run pipe_robot_sim layout_check <모델>                     # 검사만
ros2 run pipe_robot_sim layout_check <모델> --plot 배치도.png   # 배치도 그림
ros2 run pipe_robot_sim layout_check <모델> --apply             # 질량·무게중심을 robot.yaml에 반영
```

- `layout.yaml` 형식은 [02 차체 모델](02_차체_모델.md) 4절. 마디 수는 제한 없습니다.
- 검사 항목: 몸통 안, 마디 길이, 바퀴 모듈 공간 침범, 부품끼리 겹침.
- `components.urdf.xacro`를 만들어 Gazebo·RViz에 부품 상자를 보이게 합니다.

## 8. 실행 중 프로세스 정리 (주의)

- Ctrl+C로 끈 뒤 `ign gazebo`가 남을 수 있습니다. `ps -eo pid,args | grep -E "ign gazebo|lib/pipe_robot_sim" | grep -v grep`으로 확인하고 PID로 끄세요.
- `pkill -f "<명령 문자열>"`은 그 문자열을 가진 **내 셸도 같이 죽이는 경우**가 있습니다 (종료 코드 144).
- bench는 실행마다 표식(`PIPE_BENCH` 환경변수)을 붙여 실행 전후로 남은 프로세스를 정리합니다 ([06](06_알려진_문제.md) 1번).
