# 01. 구조와 실행

## 1. 폴더 구성

```
Capstone_sim/
  README.md                       실행 요약
  src/pipe_robot_sim/
    config/courses.yaml           배관 규격, 엘보 프리셋, 코스 정의
    config/sim.rviz               RViz 설정
    launch/sim.launch.py          실행 진입점 (모델·배관·노드를 한 번에 띄움)
    models/<이름>/                차체 모델
        <이름>.urdf.xacro         로봇 모양 (링크, 관절, 바퀴, 센서)
        robot.yaml                파라미터 (모델과 노드가 같이 읽음)
        layout.yaml               (two_real 계열) 부품 배치
    pipe_robot_sim/*.py           노드와 도구
  bench/                          벤치 결과 (csv), 로그 (*_logs/), 스윕 스크립트
  docs/                           이 문서
```

## 2. 빌드

```bash
cd ~/Capstone_sim
source /opt/ros/humble/setup.bash
colcon build --symlink-install
source install/setup.bash
```

- `--symlink-install`이라 **yaml·xacro 수정은 재빌드 없이 바로 반영**됩니다.
- 새 실행 파일(console_scripts)을 추가했을 때만 다시 빌드합니다.

## 3. 실행

```bash
ros2 launch pipe_robot_sim sim.launch.py course:=demo3d model:=two_real
# 다른 터미널에서 전진 명령 (5 cm/s)
ros2 topic pub -r 10 /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.05}}"
```

| 인자 | 값 | 설명 |
|---|---|---|
| `course` | `straight`, `elbow45`, `elbow90`, `demo`, `elbow45_up`, `elbow45_down`, `elbow90_up`, `elbow90_down`, `demo3d` | 배관 코스 (`courses.yaml`) |
| `model` | 폴더 이름 (기본 `three_wheel`) | 차체 모델 |
| `fitting90` | `dv90`, `dv_ll90`, `ts90` | 코스 안의 90° 엘보 교체 |
| `fitting45` | `dv45`, `ts45` | 코스 안의 45° 엘보 교체 |
| `suspension` | `all`, `top` | 바퀴 스프링 구성 (일부 모델) |
| `imu_mode` | `gyro`, `orientation` | 추정 자세 계산 방식 |
| `gui` | `true`, `false` | Gazebo 창 |
| `rviz` | `true`, `false` | RViz 창 |
| `fullscreen` | `true`, `false` | Gazebo 창을 화면 크기로 (창 크기만 바꿈) |

- 창 없이 돌리려면 `gui:=false rviz:=false`.
- ToF 센서(`tof: true` 모델)는 렌더링이 필요해서 화면이 있는 환경에서만 동작합니다. 벤치는 `DISPLAY`가 없으면 `:0`을 자동으로 빌립니다.

## 4. 노드

| 노드 | 역할 | 쓰는 모델 |
|---|---|---|
| `encoder_sim` | 바퀴 관절 각도를 엔코더 카운트로 바꿈 (CPR 기준) | 바퀴형 전부 |
| `motor_driver` | `/cmd_vel`을 바퀴 토크로 바꿈. 모드: `speed_pid`(바퀴별 속도 PID), `open_loop`(피드백 없음), `diff`(평균 속도만 PID, 모든 바퀴 같은 토크) | 바퀴형 전부 |
| `odometry` | 엔코더 + IMU 추측항법. 정답(`ground_truth`)과 위치 오차를 로그로 출력 | 전부 |
| `joint_follow` | 관절 서보 명령. `follow_mode: oracle`(배관 중심선 사용, 상한 확인용) 또는 `sensor`(ToF + IMU + 엔코더만) | three_segment, two_active, two_real |
| `oracle_steer` | 좌우 궤도 속도차로 조향 (배관 중심선 사용) | tracked |
| `clamp_torque` | 꼭짓점 클램프 토크 (일정 토크 모드) | pirate_v |
| `pipe_markers` | RViz용 배관 표시 | 전부 |
| `bench` | 모델 × 배관 일괄 주행과 평가 (헤드리스) | 도구 |
| `layout_check` | 부품 배치 검사, 질량·무게중심 계산, 배치도 그림 | 도구 |
| `generate_world` | 배관 SDF 파일만 생성 | 도구 |

## 5. 주요 토픽

| 토픽 | 타입 | 내용 |
|---|---|---|
| `/cmd_vel` | Twist | 목표 전진 속도 (`linear.x`), 조향 (`angular.z`) |
| `/wheel_encoders` | Int64MultiArray | 바퀴별 누적 엔코더 카운트 |
| `/imu` | Imu | 200 Hz, MPU6050 수준 노이즈 |
| `/joint_states` | JointState | 모든 관절 각도와 속도 |
| `/servo/<관절>` | Float64 | 능동 관절 각도 명령 [rad] |
| `/motor/<관절>/torque` | Float64 | 바퀴 토크 명령 [N·m] |
| `/tof/front`, `/tof/left`, `/tof/right` | LaserScan | ToF 거리 (왼쪽·오른쪽은 3×3 광선) |
| `/tof/front/points` | PointCloud2 | 전방 8×8 멀티존 ToF |
| `/ground_truth/odom` | Odometry | Gazebo 정답 자세 (평가용) |
| `/odom` | Odometry | 추정 자세 (엔코더 + IMU) |
| `/gz_poses` | TFMessage | 링크별 정답 자세 (벤치의 마디 정렬 평가용) |

## 6. 벤치마크 실행

```bash
cd ~/Capstone_sim
source install/setup.bash
export ROS_DOMAIN_ID=77 IGN_PARTITION=bench
ros2 run pipe_robot_sim bench --models two_real \
    --courses straight elbow90 demo3d --fittings "" dv_ll90 ts90 \
    -o bench/결과이름.csv
```

- 결과는 `bench/결과이름.csv`, 실행 로그는 `bench/결과이름_logs/`에 저장됩니다.
- 조합 1개당 헤드리스로 약 40~60초 걸립니다.
- 벤치 실행 중에는 다른 시뮬을 띄우지 마세요. 같은 토픽을 써서 결과가 섞입니다.
- 평가 항목과 합격 기준은 [04 벤치마크 기준](04_벤치마크_기준.md)을 보세요.

## 7. 부품 배치 검사

```bash
ros2 run pipe_robot_sim layout_check two_real                     # 검사만
ros2 run pipe_robot_sim layout_check two_real --plot 배치도.png   # 배치도 그림
ros2 run pipe_robot_sim layout_check two_real --apply             # 질량·무게중심을 robot.yaml에 반영
```

- `layout.yaml`에 부품 위치·크기·질량을 적으면 마디 안에 들어가는지 자동으로 검사합니다.
- 검사 항목: 몸통 안, 마디 길이, 바퀴 모듈 공간 침범, 부품끼리 겹침.
- `allow:`로 의도적으로 겹치는 부품을 지정할 수 있습니다.
- `components.urdf.xacro`를 만들어 Gazebo에 부품 상자를 보이게 합니다.

## 8. 실행 중 프로세스 정리 (주의)

- 시뮬 프로세스를 `pkill -f "<명령 문자열>"`로 죽이면, 그 명령 문자열을 가진 **내 셸도 같이 죽는 경우**가 있습니다 (종료 코드 144).
- 정리는 프로세스 이름 목록을 담은 스크립트 파일로 하거나, 벤치처럼 실행마다 표식(`PIPE_BENCH` 환경변수)을 붙여 찾아 끄는 방식을 쓰세요.
- 벤치는 2026-10-15부터 실행 전후로 표식이 붙은 프로세스를 모두 끕니다 ([06 알려진 문제](06_알려진_문제.md) 1번).
