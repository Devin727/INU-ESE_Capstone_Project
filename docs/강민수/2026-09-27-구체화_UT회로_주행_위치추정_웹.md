## 1. UT 펄서-리시버 회로

### 참고 특허 US7104131B2 — Ultrasonic pulser-receiver

[Google Patents](https://patents.google.com/patent/US7104131B2/en) / [USPTO PDF](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/7104131)

- **구성**: 회로기판 하나에 펄서 + 보호회로 + 증폭회로를 함께 올리고, 탐촉자를 케이블 없이 기판에 직접 연결 → 케이블 임피던스 부정합 회피
- **우리 설계와의 관계**: 펄서 + T/R 보호 + 프리앰프를 한 기판에 올리는 구조가 같음. 2004~2005년경 출원이라 만료 가능성이 높음 (법적 상태 미확인)
- **적용**: 탐촉자를 PCB에 최대한 가깝게 → 로봇 탑재 소형 PCB 방향과 맞음

### 회로 블록 구성

```text
ESP32 (RMT로 100~200ns 펄스) → 게이트 드라이버 → HV MOSFET → 탐촉자
                                                        ↓
              ESP32 캡처 타이머 ← 비교기 ← 프리앰프 ← T/R 보호 다이오드
                        (테스트 단계: 프리앰프 출력 → 오실로스코프)
```

- ESP32 일반 GPIO는 수백 ns 펄스를 안정적으로 못 만듦 → **RMT 주변장치** 사용 (12.5 ns 단위)
- T/R 보호는 1N4148 역병렬 다이오드로 충분하다고 봄 (1~2.25 MHz 대역 기준)

### 회로도 (부품값 포함, KiCad 작성용)

```text
[펄서부]
                 R_ch 47k
  HV(+60~100V) ───────────┬─────────────────────────┐
                            │                        │
                        C_p 4.7nF/250V           R_d 100Ω (댐핑)
                            │                        │
              ┌─────────────┼────────────────────────┼───● 노드 A
              │             │                        │
   ESP32 RMT ─► TC4427 ──► G │ Q1 (N-MOSFET 200V)     │
   (150~220ns)              D┴────────────────────────┴─── GND
                            S
                            │
                           GND

  노드 A ───●─── SMA ─── 탐촉자 (2.25MHz)
           │
[수신부]  │
           └── R_s 1k ──●──────► (+) U1 고속 op-amp ──●──► 스코프 (1단계)
                        │           G = 1+Rf/Rg      │
                    D1▓▓D2         (예: 10k/1k → x11)  └──► (+) U2 비교기 ──► ESP32 캡처 (2단계)
                  (1N4148 역병렬)                        (-) ← 임계값 (가변저항)
                        │
                       GND

[전원]
  LiPo 7.4V ─┬─► 5V 레귤 ─► TC4427, op-amp
             ├─► 3.3V 레귤 ─► ESP32
             └─► HV 승압 모듈 ─► HV
  * HV GND와 로직 GND는 한 점에서만 연결 (스타 그라운드)
```

- **동작**: C_p가 R_ch를 통해 HV로 충전 → ESP32 펄스로 Q1 ON → 노드 A가 순간 GND로 떨어지며 탐촉자에 음의 스파이크 인가 → 반사 에코는 같은 노드 A에 수 mV~수십 mV로 돌아옴 → D1/D2가 고전압은 자르고 작은 에코는 통과 → U1 증폭
- **값 조정**: 에코가 작으면 HV를 올리거나 Rf를 키움. 링잉이 길면 R_d를 낮춤(50 Ω). 펄스 폭은 탐촉자 반주기 (2.25 MHz → 약 220 ns, 5 MHz → 약 100 ns)

### 균열 검출 원리 — 수직 vs 사각 탐촉자

- **수직 탐촉자 (1차 채택)**: 벽 두께 방향으로 쏨. 후벽 에코 ToF = 두께. 균열·부식으로 두께가 줄면 ToF가 짧아지고, 벽 내부 균열이 있으면 후벽보다 **먼저 오는 에코**가 생김 → 이상 판정
- **사각 탐촉자 45°/60° (확장)**: 표면에 수직으로 갈라진 세로 균열은 수직 탐촉자가 스쳐 지나가 못 잡음. 비스듬히 쏘면 균열 면에 정면으로 부딪혀 강하게 반사. 실제 피그 검사가 이 방식
- 1차 데모는 홈(두께 감소형)이라 수직 탐촉자로 잡힘. 세로 균열까지 가려면 사각 탐촉자 추가 (+약 10만원, 추정)

## 2. 벽 밀착 구동

### 스프링 밀착 원리

바퀴형 배관 로봇은 구동 모듈 + 바퀴를 관벽에 누르는 기구로 구성. 벽 파지력이 부족하면 미끄러짐 ([ScienceDirect](https://www.sciencedirect.com/science/article/abs/pii/S0094114X06002254)).

수동 스프링 방식은 관경 변화·마찰 변화·제작 공차에 민감 → **1차 목표를 100 mm 단일 관경으로 고정**. 힘센서 폐루프 제어는 범위 밖.

### 슬라이더-크랭크 + 스프링 (당시 채택안)

[PMC 논문](https://pmc.ncbi.nlm.nih.gov/articles/PMC10886735/)

- 슬라이더-몸체 사이 스프링으로 바퀴가 관을 누름. 관경이 바뀌면 크랭크가 회전해 바퀴 위치 자동 조정
- 바퀴별 스프링 독립 → 엘보 통과에 유리
- 적용: 100 mm 기준으로 설계하되 스프링 스트로크를 ±15 mm 정도 주면 75 mm 확장 여지

### 스프링 강성 설계 포인트

[arXiv 2105.10447](https://arxiv.org/pdf/2105.10447)

- 로봇 무게가 아래쪽 바퀴 수직항력을 늘려주므로 **위쪽 바퀴가 접촉을 잃기 쉬움** → 위쪽 바퀴 기준으로 스프링 선정
- 실무: 스프링 상수 3종(예: 0.3 / 0.5 / 0.8 N/mm)을 사서 교체하며 미끄러짐 없는 최소 강성 찾기
- 목표 접촉력: 바퀴당 3~5 N. 고무 바퀴 마찰계수 0.6 가정 시 바퀴 4개 합산 견인력 7~12 N → 로봇 무게(약 500 g, 5 N)의 1.5배 이상 (추정 계산)

### 우리 스케일 선행 사례

- 80~100 mm 관 T자 구간용, 체인마다 조향 바퀴 + 구동 바퀴 하나씩 둔 2열 체인 로봇 — [ACES 리뷰](https://arxiv.org/pdf/2405.09925) Figure 7
- PIRATE (트벤테대): 상하 바퀴로 주행 + 클램핑 겸용, 수직 이동까지 — [U-Today](https://www.utoday.nl/science/63800/Snake_robot_for_pipe_inspection_)

### 부품 배치 (앞 → 뒤)

```text
[전방]  카메라+LED링 │ VL53L0X 거리센서
        ─────────────┼─────────────────
        UT 보드 + 탐촉자(하단, 서보 암) │ ESP32
        ─────────────┼─────────────────
        Pi Zero 2W │ 모터 드라이버 │ IMU
        ─────────────┼─────────────────
[후방]  LiPo 2S │ 전원 보드 │ 테더 고리

바퀴: 상단 2개 (앞·뒤), 하단 2개 (앞·뒤) — 하단 2개 구동, 상단 2개 종동(스프링 클램핑)
```

- 탐촉자는 몸체 **하단 중앙**: 관 바닥이 제일 오염이 적고 접촉이 안정적일 것으로 봄
- IMU는 몸체 중심 가까이 → 회전 감지 정확도
- 배터리를 후방에 두면 무게중심이 뒤로 → 전방 바퀴가 엘보에서 살짝 들려도 후방이 버팀

### 제작 방식

- 몸체: 3D 프린팅 PLA, 앞·중·뒤 3분할 → 부품 교체 쉽게
- 바퀴 암: PLA + 압축 스프링 + M3 핀 힌지
- 서보 암: SG90 + PLA 암 + 볼조인트(RC 링키지용) + 탐촉자 홀더
- 조립 후 관에 넣어 스프링 강성 3종 중 미끄러짐 없는 최소값 선택

## 5. 제작 순서와 주의점

### 1단계 — 회로 검증 (오실로스코프)

1. **만능기판**으로 제작 — 브레드보드는 고전압·MHz 신호에서 노이즈가 심함
2. HV를 **30~50 V부터** 올리며 스코프로 펄스 파형 확인
3. PVC 정상부에 탐촉자를 대고 **후벽 에코** 확인 → 벽 두께 × 2 ÷ 2,258 m/s로 계산한 시간과 비교
4. 인위 균열 시편(깊이별)에서 **후벽보다 먼저 오는 에코** 확인
5. 노이즈 레벨을 보고 비교기 임계값 결정

### 2단계 — 전용 PCB (로봇 탑재)

- 비교기 + ESP32 Input Capture로 ToF 검출 → 고속 ADC 불필요
- ESP32 캡처 타이머 80 MHz → 약 12.5 ns 분해능 → PVC 두께 분해능 약 0.014 mm (계산값)
- KiCad로 설계 → JLCPCB 등 소량 제작 (1~3만원). SMD 부품으로 수 cm급
- 대가: 임계값을 넘은 시각만 알기 때문에 노이즈 오검출 가능 → 1단계에서 노이즈 레벨 충분히 확인

### 주의점

- **탐촉자 주파수**: PVC 감쇠 약 1.8 dB/mm → 5 MHz는 신호가 거의 안 살아남을 가능성이 크다고 봤음 (당시 판단. 이후 5 MHz를 구매했으므로 실측으로 확인 필요)
- **고전압**: 50~100 V라도 주의. HV부와 로직부 물리적 분리, 절연 간격 확보
- **노이즈**: HV 펄스가 ESP32에 노이즈 유발 → 그라운드 분리·디커플링. 가장 많이 막히는 지점
- **펄스 폭**: 탐촉자 주파수 반주기
- **케이블 길이**: 탐촉자~기판 최대한 짧게 (US7104131B2)
- **커플런트**: 공기층이 있으면 초음파가 안 들어감. 젤 필수
- **디버깅**: 펄서/수신부/탐촉자 중 어디 문제인지 스코프로 단계별 확인

## 6. 보드별 구현 상세 (당시 안)

### ESP32 — 검사 담당

#### 펄스 생성 (RMT)

일반 `digitalWrite`는 수백 ns 펄스를 못 만듦 → RMT 주변장치 사용. 80 MHz 클럭 기준 1 tick = 12.5 ns

```cpp
#include "driver/rmt_tx.h"
// 2.25MHz 반주기 ≈ 220ns → 약 18 tick
rmt_symbol_word_t pulse = {
  .duration0 = 18, .level0 = 1,   // HIGH 220ns
  .duration1 = 18, .level1 = 0
};
rmt_transmit(tx_chan, encoder, &pulse, sizeof(pulse), &cfg);
```

출력 핀 → TC4427 입력

#### ToF 측정 (MCPWM 캡처)

비교기 출력을 캡처 핀에 연결. 펄스 발사 시각과 에코 도착 시각을 하드웨어 타이머로 잡음

- t_fire = 펄스 발사 순간, t_echo = 비교기 첫 상승 엣지
- ToF = (t_echo − t_fire) × 12.5 ns → 두께 = ToF × 2258 / 2
- **블랭킹**: 펄스 직후 수 µs는 링잉으로 비교기 오동작 → 3 µs 블랭킹 후 첫 엣지만 유효
- 벽 10 mm 기준 ToF ≈ 8.9 µs (VG1 6.6 mm는 약 5.8 µs)

#### 측정 프로토콜 (지점마다)

1. Pi로부터 MEASURE 수신 (측정 ID 포함)
2. 서보 압착 (ESP32가 직접 제어)
3. 펄스 10회 발사, ToF 10개 수집
4. 중앙값(median)으로 노이즈 억제
5. Pi에 `TOF,<id>,<값>,<유효횟수>` 응답. 유효 5회 미만이면 `NOECHO,<id>`
6. 서보 해제

#### 핀 배치 (예시)

| 기능 | 핀 |
| --- | --- |
| RMT 펄스 출력 | GPIO 18 |
| 캡처 입력 (비교기) | GPIO 19 |
| UART TX/RX (Pi) | GPIO 17/16 |
| 서보 PWM (탐촉자 암) | GPIO 21 |
| 배터리 전압 ADC | GPIO 34 |
| 피크검출 ADC (확장) | GPIO 35 |

### Pi Zero 2W — 주행·기록 담당 (당시 안, 이후 주행은 ESP32로 이동)

#### 역할

- 모터 드라이버 제어, 엔코더로 이동거리 누적, IMU로 엘보 통과 감지
- 50 mm마다 정지 → ESP32에 MEASURE → 결과 기록 → 재출발
- 카메라 촬영(선택), 모든 데이터 CSV 로컬 저장

#### 배선

| 기능 | 연결 |
| --- | --- |
| 모터 드라이버 (TB6612) | GPIO PWM 2채널 + 방향 4핀 |
| 엔코더 A/B | GPIO 인터럽트 2채널 (모터당) |
| IMU (MPU6050) | I2C |
| ESP32 | UART (`/dev/serial0`) |
| 카메라 | CSI |
| 전방 거리센서 (VL53L0X) | I2C |

#### 주행 루프

```python
measure_id = 0
while not end_of_pipe:
    drive_forward(until=encoder_delta >= 50)   # mm
    stop()
    pos = encoder.total_mm()                    # 측정 시점 위치 고정
    measure_id += 1
    esp.send(f"MEASURE,{measure_id}")
    tof = esp.read()          # "TOF,17,8912,10" or "NOECHO,17"
    yaw = imu.read_yaw()
    log.write(measure_id, pos, tof, yaw, timestamp)
    if abs(yaw - prev_yaw) > 30:
        log.mark("ELBOW")
    if front_dist < 50:
        end_of_pipe = True
```

- 50 mm 간격이면 4 m 관에서 80회 측정 → 측정당 약 1초 → 총 2~3분 (추정)
- 위치는 **MEASURE를 보내는 순간**의 엔코더 값으로 고정. 응답을 받은 시점이 아님

#### 데이터 형식 (CSV)

```text
id, pos_mm, tof_ns, valid_cnt, yaw_deg, flag
1,  0,      8912,   10,        0.2,     OK
2,  50,     8905,   10,        0.1,     OK
3,  100,    4210,   9,         0.3,     EARLY_ECHO   ← 균열 후보
4,  150,    0,      2,         0.2,     NOECHO
```

### UART 통신 규약 (115200)

| Pi → ESP32 | ESP32 → Pi |
| --- | --- |
| `MEASURE,<id>\n` | `TOF,<id>,<ns>,<valid>\n` 또는 `NOECHO,<id>\n` |
| `SERVO,<각도>\n` | `OK\n` |
| `BATT?\n` | `BATT,<mV>\n` |

텍스트 한 줄 형식 → 시리얼 모니터로 바로 디버깅 가능

### 전원

- LiPo 2S 1500 mAh (7.4 V) 하나. 예상 소모: 모터 4개 0.5 A + Pi 0.4 A + 기타 0.2 A ≈ 1.1 A → 약 1시간 구동 (추정), 데모 3~5분이면 충분
- → 5 V 레귤레이터 → Pi, 모터 드라이버 로직, 서보
- → 3.3 V 레귤레이터 → ESP32 (노이즈 때문에 Pi에서 빼지 않고 별도)
- → HV 승압 모듈 → 펄서
- 모터 전원은 7.4 V 직결 (드라이버 VM)
- 서보 압착 순간 전류가 튐 → 서보 전원 라인에 1000 µF 커패시터
- **HV GND와 로직 GND는 한 점에서만 연결** (스타 그라운드)

## 7. 파형 분석

### 파형 전체를 읽지 않는 이유

5 MHz급 반사파를 파형째 읽으려면 초당 수천만 회 샘플링하는 고속 ADC가 필요 (pic0rick이 60 Msps ADC를 쓴 이유). ESP32 내장 ADC는 2 Msps급, Pi Zero는 고속 ADC 없음.

- 고속 ADC를 로봇에 넣으면 부피·전력이 커져 테더 방식으로 돌아가게 됨
- 대신 **"반사파가 언제 왔는가"만 검출**하면 비교기 하나 + ESP32 타이머로 충분 → HC-SR04 원리를 MHz 대역에 적용
- 잃는 것: 스펙트로그램·CNN 분류. 대신 "정상 대비 이상"은 판별 가능하다고 봄

### 1단계 — 스코프에서 볼 것

스코프 시간축 기준 (벽 두께 약 10 mm 가정):

```text
0µs      여기 스파이크 (수십 V, 200ns)
0~3µs    링잉 (탐촉자 자체 진동, 서서히 감쇠)
~8.9µs   후벽 에코 (10mm × 2 ÷ 2258m/s)       ← 정상의 기준
~17.8µs  2차 반사 (후벽 에코의 왕복)
```

비교할 시편 (벽 10 mm 가정, 계산값):

| 시편 | 예상 후벽 ToF | 비고 |
| --- | --- | --- |
| 정상 (10 mm) | 8.9 µs | 기준값 |
| 홈 2 mm (남은 두께 8 mm) | 7.1 µs | 에코가 앞당겨짐 |
| 홈 5 mm (남은 두께 5 mm) | 4.4 µs | 더 앞당겨짐 + 진폭 커짐 (감쇠 1.8 dB/mm라 경로가 짧을수록 큼) |

기록할 것: 도착 시간, 진폭, 후벽 에코 유무, 후벽 앞 추가 에코 유무, 노이즈 바닥 레벨. 이 파형들을 CSV로 저장하면 웹에서 "참고 파형"으로 표시 가능.

### 2단계 — ToF 기반 판정 규칙

측정 지점마다 10회 발사 → 유효 캡처 수와 중앙값으로 3분류:

| 분류 | 조건 | 의미 |
| --- | --- | --- |
| **OK** | 유효 ≥ 5, ToF가 기준의 80~120% | 정상 |
| **EARLY_ECHO** | 유효 ≥ 5, ToF < 기준의 80% | 두께 감소 또는 내부 균열 후보 |
| **NOECHO** | 유효 < 5 | 접촉 불량(젤 부족, 곡면 미밀착) 또는 심한 결함 |

- 기준 ToF = 주행 시작 후 첫 5개 OK 지점의 중앙값 (관마다 자동 캘리브레이션)
- NOECHO는 **서보 해제 → 재압착 → 재측정 1회** 후 판정. 두 번 다 NOECHO면 `CONTACT_FAIL`로 기록하고 이동 (결함으로 단정하지 않음)
- EARLY_ECHO가 연속 2지점 이상이면 이상 구간으로 묶음
- 블랭킹 3 µs 안에 잡힌 엣지는 무시 (링잉)

### 오검출 방지

- **젤 부족 vs 결함**: 둘 다 에코가 약해짐. 재접촉 재측정으로 구분 — 젤 부족이면 재접촉 후 회복, 결함이면 그대로
- **이음매(유니온) 반사**: 커플링 지점은 두께가 급변해 EARLY_ECHO처럼 보임 → 이음매 위치를 알고 있으니 ±30 mm는 판정 제외 (위치 보정 마커로 활용, 8절)
- **노이즈 임계값**: 1단계 스코프에서 노이즈 바닥의 3배 이상으로 비교기 임계값 설정
- **엘보 안**: 곡면이라 탐촉자 밀착이 불확실 → yaw 변화 중에는 측정 생략

### 확장 — 진폭 읽기

ToF만으로는 "얼마나 심한지"를 못 봄. 피크검출 회로(쇼트키 다이오드 + 커패시터 + 방전 저항)를 추가하면 에코 최대 진폭이 커패시터에 남아 ESP32 ADC로 읽을 수 있음.

- 진폭이 크면 얕은 결함(경로 짧음), 작으면 접촉 불량 → NOECHO 원인 구분에 도움
- 사각 탐촉자 추가 시 균열 반사 세기로 크기 추정 가능
- 고속 ADC 없이 되는 범위의 확장. 1차 필수 아님

## 8. 위치추정·맵 생성

### 완전 SLAM을 하지 않는 이유

| 문제 | 배관 내부에서 |
| --- | --- |
| GPS | 불가 |
| 라이다 SLAM | 벽이 다 똑같이 생겨 특징점 부족, 오차 누적 |
| 비전 SLAM | 어둡고 반복 무늬, 조명을 달아도 곡면 반사 |
| 엘보·T자 | 로봇 자세 변화가 커서 추정 흔들림 |
| 미끄러짐 | 관 바닥이 매끄러우면 엔코더가 헛돎 |

상용 로봇도 대부분 완전 3D 맵이 아니라 **"입구에서 몇 m 지점"** 방식 (R-Scan 인코더). 배관에서는 1자유도 위치추정이 실용적 → 같은 방식 채택 제안.

### 3층 위치추정

```text
[기본]  엔코더  → 이동거리 누적 (바퀴 둘레 × 회전수)
[방향]  IMU yaw → 30° 이상 변하면 엘보. 45°/90° 구분
[보정]  이음매  → 유니온 통과 시 위치 리셋
```

**이음매 보정 원리**: 유니온 커플링 지점은 두께가 급변해 ToF가 튀거나 NOECHO가 남. 테스트 배관은 직접 만들기 때문에 이음매 간격을 알고 있음 → "N번째 이음매 통과"를 감지하면 엔코더 누적값을 그 이음매의 실제 위치로 덮어씀. 셰필드 연구가 하수관에서 이음매 검출로 위치추정한 것과 같은 원리 (해당 연구에서 ORB-SLAM3보다 정확했다고 보고).

근거:

- 셰필드: 이음매 검출 위치추정, 150~600 mm 실제 하수관 30~90 m에서 검증
- MIT: IMU + 엔코더 + EKF로 이동거리 대비 오차 0.5% (시뮬레이션)
- Pipebots: 음향 매핑 2 cm 정확도, 실시간 전송 없이 저장 후 분석

### 맵 표현

노드–엣지 리스트. 절대 좌표 아님.

```text
[START] ─1000mm─ [ELBOW_45] ─500mm─ [ELBOW_90] ─1000mm─ [TEE] ─500mm─ [END]
```

- 노드: START / ELBOW_45 / ELBOW_90 / TEE / END — IMU yaw 변화량과 전방 거리센서로 판별
- 엣지: 엔코더 거리 (이음매 보정 적용)
- 웹에서 yaw 누적으로 2D 꺾은선으로 그림. 정확한 좌표가 아니라 "구조 + 구간 길이"가 목표
- 주행 중에는 (id, pos, yaw)만 저장하고 회수 후 웹에서 구성 → 로봇 내 실시간 연산 없음

### 맵과 결함의 분리 기록

팀 문서(9/18)의 "형상 지도를 먼저 만들고, 검출 당시 위치를 기록해 이후 지도에 반영" 방식.

- 주행 중: 측정 ID마다 (pos, yaw, ToF, flag) 한 줄
- 회수 후: ① yaw로 노드 추출 → 맵 ② 같은 pos 축에 flag 얹기 → 결함 위치
- 실시간 결합을 안 하니 Pi 부담 없음. 측정 ID로 묶여 있어 어떤 파형이 어느 위치인지 재추적 가능

### 예상 정확도 (추정)

- 엔코더 단독: 4 m에서 ±5~10 cm (미끄러짐)
- 이음매 보정 시: 이음매 사이(0.5~1 m)마다 리셋 → ±2~3 cm
- 측정 간격 5 cm이니 "어느 측정 지점"까지 특정 가능. 실측 균열 위치와 비교해 오차 산출

### 범위 밖 — 미지 배관 탐색

- 1차는 **알려진 구조(직접 만든 테스트 배관)**에서 위치를 정확히 찍는 것
- 미지 배관에서 분기 발견 → 탐색 → 복귀(DFS)는 T자 진입 조향까지 필요해서 범위 밖. 팀 통합 시 다른 팀원 매핑 알고리즘과 연결 검토
- 측면 거리센서로 관경·중심을 추정하면 엔코더 미끄러짐 보정에 도움 → 통합 단계에서 검토

## 9. 실제 주행 시나리오 (제안)

### 데모 배관 구성

```text
[입구] ─ 직관 1m ─ 45° 엘보 ─ 직관 0.5m ─ 90° 엘보 ─ 직관 1m ─ T자 ─ 직관 0.5m ─ [막힘]
                  ▲                              ▲              ▲
              균열 A (얕음)                  균열 B (깊음)    정상 (대조)
```

- PVC 100 mm, 건자재114 4 m 1본을 절단
- 균열 깊이 2 mm / 5 mm, 버니어캘리퍼스로 실측값 기록
- 유니온 커플링으로 구간 교체 가능 → 균열 위치를 매번 바꿔 "위치 암기 아님"을 보임
- 관 끝은 마개로 막아 종료 조건을 만듦

### 주행 단계

| 단계 | 로봇 동작 | 기록 |
| --- | --- | --- |
| 1. 직관 주행 | 50 mm 전진 → 정지 → 압착 → 10회 측정 → 해제 → 전진 반복 | id, pos, ToF, yaw |
| 2. 45° 엘보 | 스프링 바퀴가 곡면을 따라감. yaw 변화 30° 이상 감지 시 ELBOW 마킹. 엘보 안에서는 측정 생략 | ELBOW 플래그 |
| 3. 균열 A 통과 | ToF가 후벽보다 짧게 나옴 (EARLY_ECHO) | 균열 후보 기록 |
| 4. 90° 엘보 | 차동구동으로 한쪽 바퀴 감속, yaw 90° 변화 확인 | ELBOW 플래그 |
| 5. 균열 B 통과 | EARLY_ECHO + ToF가 A보다 더 짧음 → 더 깊은 균열 | 균열 후보 기록 |
| 6. T자 | 1차는 **직진만**. 전방 거리센서로 T자 벽 감지 시 직진 방향 판단 | T자 통과 |
| 7. 종료 | 전방 50 mm 이내 막힘 감지 → 정지, LED 점등, CSV 닫기 | 종료 로그 |
| 8. 회수 | 테더 줄로 당겨 회수 (또는 후진 명령) | — |
| 9. 분석 | SD카드 → 노트북 → 웹 대시보드 | 정확도 산출 |

예상 소요: 4 m 기준 3~5분 (추정)

```text
CSV 업로드 → FastAPI 백엔드 → 분석 → React/Plotly 대시보드 → LLM 리포트
```

1. **업로드**: 회수한 SD카드 CSV를 웹에 드래그
2. **기준값 산출**: 정상 구간(flag=OK) ToF 중앙값 = 기준 두께
3. **이상 판정**: 기준 대비 ToF가 20% 이상 짧거나 EARLY_ECHO 연속 2회 → 이상 구간. CONTACT_FAIL은 "미측정"으로 별도 표시
4. **경로 재구성**: yaw 변화점을 엘보로, 엔코더 거리로 구간 길이 → 노드–엣지 → 2D 선형 지도
5. **시각화**: 지도 위에 이상 구간 빨간 표시, 클릭하면 위치·ToF·추정 두께 감소율
6. **LLM 리포트**: 이상 구간 목록을 프롬프트로 넣어 "3.2 m 지점, 두께 약 40% 감소 추정, 우선 점검 권장" 식 요약문 생성
7. **정답 비교**: 실측 균열 위치를 입력하면 검출 위치와의 오차(cm) 자동 계산

### 기술 스택

| 계층 | 선택 | 이유 |
| --- | --- | --- |
| 백엔드 | FastAPI (Python) | 분석 코드(numpy/pandas)와 같은 언어 |
| 프론트 | React + Plotly | 그래프 인터랙션 |
| LLM | 외부 LLM API 또는 로컬 Ollama | 리포트 문장 생성만, 판정은 규칙 기반 |
| 저장 | SQLite | 주행 회차별 기록, 단순 |
| 배포 | 로컬 노트북 | 데모용, 서버 불필요 |

### 화면 구성

- **좌측**: 배관 경로 지도 (직관·엘보·T자 아이콘, 이상 구간 빨간 점, 미측정 회색 점)
- **우측 상단**: 위치별 ToF 꺾은선 그래프, 기준선 표시. 1단계 스코프 참고 파형 토글
- **우측 하단**: 이상 구간 표 (위치, ToF, 추정 두께 감소율, 실측 대비 오차)
- **하단**: LLM 생성 리포트 텍스트, 복사 버튼

## 11. 범위에서 제외한 것 (당시 판단)

| 항목 | 이유 |
| --- | --- |
| 5 MHz 탐촉자 | PVC 감쇠가 커서 신호 확보가 어렵다고 봄 (이후 5 MHz 구매 → 실측 필요) |
| 힘센서 폐루프 파지력 제어 | 캡스톤 범위 초과. 스프링 수동 방식으로 충분하다고 봄 |
| 75 ↔ 100 mm 완전 가변 | 1차는 100 mm 고정. 스프링 스트로크로 여지만 남김 |
| 탄성 패드 커플링 | PVC에서 신호 손실 불확실. 젤로 먼저 |
| 파형 분석·CNN 분류 | 고속 ADC 필요. ToF 이상탐지로 대체 |
| 카메라/라이다 SLAM | 배관 내 특징점 부족. 엔코더 + IMU + 이음매 보정으로 대체 |
| 미지 배관 분기 탐색 (DFS) | T자 진입 조향 필요. 1차는 알려진 구조 |
| 실시간 무선 전송 | T분기 신호 단절, 배터리 소모. 저장 후 회수 (Pipebots 방식) |
| T자 분기 진입 | 조향 로직 필요. 1차는 직진만 |
| 물·수직관 | 방수·클램핑 추가 과제. 후속 |

## 12. 정리

| 영역 | 이미 있는 것 | 우리가 할 것 |
| --- | --- | --- |
| UT 회로 | 펄서 + 보호 + 증폭 일체형 기판 (특허) | 같은 구조를 소형·저가로 직접 제작 + ToF 비교기로 ADC 제거 |
| 파형 판정 | 파형 전체 분석 (고속 ADC) | ToF 3분류 (OK / EARLY_ECHO / NOECHO) + 재접촉으로 접촉 불량 구분 |
| 탐촉자 접촉 | 짐벌 압착, 커플런트 보충 | 서보 암 + 볼조인트 + 젤 |
| 벽 밀착 구동 | 스프링 밀착 (성숙한 기술) | 슬라이더-크랭크 스프링, 100 mm 고정, 위쪽 바퀴 기준 설계 |
| 위치·맵 | 이음매 검출 위치추정 (셰필드), 인코더 (R-Scan) | 엔코더 + IMU + 이음매 보정, 노드–엣지 맵, 맵·결함 분리 기록 |
| 분석 | 사후 분석 (Pipebots 등) | 웹 대시보드 + LLM 리포트 |

핵심 기술 하나하나는 선행 특허·연구가 있음. 차별점은 새 기술이 아니라 **검증된 요소들을 100 mm급 PVC관용 저가 소형 로봇 하나로 통합**하는 것.
